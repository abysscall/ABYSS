# ADR-0016 — Core First: Sequential Implementation Discipline

**Status:** Accepted
**Date:** July 2026

---

## Context

ABYSS has reached a critical inflection point. The architectural vision
is mature: ADRs 0000–0015 document the decisions, the philosophy is
written, the tokenomics are implemented and tested, the social layer
data model exists. The whitepaper is 21 pages and ready for investors.

The risk at this stage is the most common failure mode in blockchain
projects: **continuing to expand the idea space while the core
implementation remains incomplete.** Many projects spend years writing
whitepapers and adding concepts without producing a working chain.

The rule: 80% of effort on implementation, 20% on research and new ideas.
New ideas do not disappear — they move to the research backlog and are
introduced only when the base platform is stable enough to support them.

---

## Decision

ABYSS enters a sequential implementation phase. The order is fixed
and each stage must reach working condition before the next begins.

### Phase 1 — Core (absolute priority)

**Stage 1: Consensus (BFT)**
- Multi-validator (replacing single-proposer devnet)
- View Change (leader failure handling)
- Finality (deterministic, not probabilistic)
- Slashing Hooks (validator misbehaviour penalties)
- Leader Rotation
- Byzantine fault tests

**Stage 2: Storage (RocksDB)**
- Blocks, state, transactions, indices
- Accounts, Genesis Registry, snapshots

**Stage 3: P2P Network**
- Peer discovery, reputation, synchronisation
- Gossip protocol, anti-spam, DoS protection
- Real nodes — not localhost

**Stage 4: JSON-RPC**
- Explorer, Wallet, SDK, API, CLI integration

**Stage 5: Wallet Core (library, not UI)**
- Address creation, signing, signature verification
- Transaction construction, seed recovery

**Stage 6: Genesis Builder**
- First native AC coin appears here
- Genesis Allocation Registry
- No ERC-20 — native only (see ADR-0015)

**Stage 7: Explorer (minimal)**
- Blocks, height, validators, TPS

**Stage 8: SDK**
- Rust, Go, Python, JavaScript

### Phase 2 — Enhancement (after stable mainnet)

Privacy Engine (zk-STARK, Ring Signatures, Stealth, Bulletproofs),
Private Smart Contracts, Shielded VM, Governance, Quantum Security,
Mixnet, FHE, MPC, Anonymous Staking, Privacy DAO.

---

## Consequences

- New ideas are not rejected. They enter the research backlog.
- No new architectural concepts are introduced until the relevant
  core stage is complete.
- Every PR/commit must map to a specific stage in Phase 1.
- The rule 80/20: 80% implementation, 20% research, until mainnet.
