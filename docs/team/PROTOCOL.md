# Протокол работы команды ABYSS (для владельца)

Зачем он нужен: несколько ИИ работают над одним проектом, и без общих правил их работа расходится (разные цифры, разные версии одного файла, правки поверх друг друга). Протокол даёт один общий «блокнот» в репозитории. Решения принимаешь ты. ИИ предлагают, проверяют и докладывают.

## 1. Участники

| Кто | Роль | Что делает | Чего не делает |
|---|---|---|---|
| Владелец | Решает | Принимает решения, пушит в GitHub, разрешает правки | Не пересылает секреты |
| Codex | Код | Работает в репозитории, запускает cargo и тесты | Не меняет документы и сайт без разрешения |
| Kimi | Независимый аудитор | Читает код и проверяет чужие выводы | Не правит файлы, пока не дана зона |
| Claude (этот чат) | Документы, сайт, тексты, сверка | Пишет файлы целиком, проверяет цифры и формулировки, сравнивает отчёты | Не видит репозиторий, не запускает cargo |
| GPT и другие | Идеи | Предлагает варианты | Его ответ — предложение, а не решение |

Зоны по папкам расписаны в `AGENTS.md`, таблица «Lanes».

## 2. Как начать работу с ИИ

**Если ИИ работает в репозитории (Codex, Kimi Code, Claude Code):** он сам читает `AGENTS.md`. Скажи одной фразой:

> Прочитай AGENTS.md, потом docs/team/HANDOFF.md и docs/team/DECISION_LOG.md. Работай только в своей зоне. Задача: …

Сведения о чтении `AGENTS.md` взяты из открытых источников на октябрь 2026. Проверь версию своего инструмента: Codex читает файл по умолчанию, Claude Code читает его, если нет `CLAUDE.md`, Kimi Code ищет только `AGENTS.md`.

**Если ИИ работает в обычном чате (Claude здесь, Kimi или GPT в браузере):** он файлы не видит. Покажи ему состояние вручную. В PowerShell:

```powershell
cd C:\ABYSS
```
```powershell
Get-Content -Encoding UTF8 docs\team\HANDOFF.md
```

Скопируй вывод в чат. При необходимости добавь `docs\team\DECISION_LOG.md`.

## 3. Как закончить работу

Скажи ИИ в репозитории:

> Добавь запись в docs/team/HANDOFF.md и покажи, какие файлы изменены (git status).

Claude в этом чате файлы не правит. Он даст готовый блок записи, а ты вставишь его наверх журнала сессий в `HANDOFF.md`.

## 4. Один писатель за раз

В `HANDOFF.md` есть строка `Active lock`. Кто начинает правки, записывает туда своё имя, задачу и файлы. Закончил — пишет `none`. Если замок висит больше суток (ИИ мог оборваться на лимите), его снимаешь ты.

## 5. Лимиты и обрывы

Codex уже упирался в лимит посреди правки. Поэтому правила такие: правки мелкими шагами, проверка после каждого шага, а при близком лимите ИИ останавливается в чистом состоянии и пишет передачу. Если подозреваешь обрыв, сделай `git status`. Список изменённых файлов покажешь следующему ИИ.

## 6. Кто кого проверяет

| Что меняется | Кто проверяет |
|---|---|
| Сайт, тексты, документы | Один другой ИИ, затем ты |
| Код, не связанный с деньгами | Один другой ИИ, затем ты |
| Консенсус, криптография, токены, учёт наград | Автор, один независимый ИИ и ты |

Проверяющему всегда говори: «Попробуй найти ошибку, а не подтвердить». Проверка, которая просто соглашается, ничего не стоит.

## 7. Разногласия

Если два ИИ спорят, ты не выбираешь того, кто уверенней. Обе позиции с доказательствами (цитата кода, вывод команды) записываются в `DECISION_LOG.md` как `OPEN`, и решаешь ты.

## 8. Чего не делать

1. Не вставляй ответ одного ИИ другому как «истину». Вставляй как «предложение для проверки».
2. Не пересылай значения `ABYSS_GATE_SECRET`, `ABYSS_ADMIN_KEY`, ключи и seed-фразы никому.
3. Не давай двум ИИ править репозиторий одновременно.

## 9. Если ИИ нарушил правила

Посмотри, что изменилось:

```powershell
git status
```

Вернуть один файл к последнему сохранённому состоянию (несохранённые правки в нём пропадут):

```powershell
git restore путь\к\файлу
```

Если не уверен, сначала покажи вывод `git status` Claude.
