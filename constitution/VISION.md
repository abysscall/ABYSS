## The Five Pillars

### 1. Identity
Every ABYSS Account is a cryptographic identity owned entirely by the user.
Not a username. Not an email. A cryptographic root of trust that the user
controls and no platform can revoke.

### 2. Native AI
Every ABYSS Account has its own Native AI — a system-level intelligence that
works for the user and no one else. It operates within the boundaries the user
sets. It cannot be commanded by external parties.

### 3. Privacy
Privacy is not a feature in ABYSS. It is part of the architecture. All state,
transactions, identity attributes, AI memory, and social data are private by
default. The user decides what to reveal, to whom, and for how long.

### 4. Policy Engine
The user expresses their rules once. The Policy Engine enforces them always.
No transaction, no AI action, no external request can bypass the policy the
user has set.

### 5. Sovereign Computation
ABYSS OS runs where the user wants it: natively on bare metal, as a runtime
environment inside Windows, macOS or Linux, or from a portable external drive.
The user's environment travels with them.

---

## The Three Modes

ABYSS OS operates in three modes depending on the user's needs:

**Native** — Full operating system installed directly on hardware.
Gives ABYSS complete control of the machine.

**Runtime** — ABYSS OS Environment installed inside an existing operating
system (Windows, macOS, Linux). The most accessible path for most users.
ABYSS runs in an isolated, secure environment alongside the host OS.

**Portable** — ABYSS OS on an external SSD or NVMe drive. The user boots
ABYSS from the external device on any compatible machine without touching the
internal disk.

## ABYSS Native AI

Every ABYSS Account includes a Native AI — not as an optional add-on but as a
core system component, equivalent in role to a process in a conventional
operating system.

The Native AI:

- operates only within the permissions the user grants it
- learns the user's preferences and workflow
- can act autonomously within defined spending and action limits
- can interact with other AI agents in the network
- can never bypass the Policy Engine
- can never access data the user has not explicitly permitted

The key principle:

> **AI is powerful but never sovereign.**

The user is always the owner. The AI is always the instrument.
